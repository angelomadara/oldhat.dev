About oldhat.dev

oldhat.dev is a live, unfiltered view of the HTTP traffic hitting a small production server — every crawler, scanner, credential harvester and human visitor, classified and counted. Nothing is sampled and nothing is filtered out, because the noise is the interesting part.

What this site is

This is a dashboard built on the Nginx access logs of two domains: oldhat.dev, the static site you are reading, and api.oldhat.dev, the JSON API behind it. Every request recorded in those logs is parsed, enriched and classified, then published here as a report you can browse by date. There is no demo data and no honeypot — this is the ordinary background traffic of a server with a public address.

The aim is documentation rather than alarm. Most of what arrives is harmless: search engine crawlers, uptime checkers, link previews, and an enormous amount of automated probing for files that were never there.

What it shows

The report is split into seven views, each with its own page:

  • Overview — daily totals split into human and bot traffic.
  • Threat Intelligence — request paths matched against known attack patterns and grouped into categories such as .env credential harvesting, .git directory probing, WordPress scanning, SQL injection attempts, admin panel brute-force and configuration file leaks.
  • Top IPs — the busiest client addresses with country, request volume, client type and the path each one requested most.
  • Bot Breakdown — automated clients identified from the User-Agent string, ranked by hits and unique IP addresses.
  • Path Activity — the most requested URLs, with their response-code split and threat category.
  • Status Codes — the overall 2xx / 3xx / 4xx / 5xx distribution.
  • Hourly Activity — request volume per hour of the day, split between total hits and bot traffic.

How a request is classified

Each log line is read for its path, status code, User-Agent and source address. The address is resolved to a country with a GeoIP lookup. The User-Agent is matched against known crawler and scanner signatures to decide whether the client is human or automated, and to name the bot where possible. The path is then matched against attack signatures and assigned a category; anything that matches no signature is counted as other.

Two details are worth knowing before reading any of the numbers:

Addresses are masked. The last two octets of every IP are replaced with asterisks. The point is to show attack patterns, not to publish a list of addresses worth poking at.

Counts are per request, not per visitor. One aggressive scanner can produce more hits in a minute than a week of human readers, so a large number in the bot columns does not mean a large audience.

How to read it honestly

A bot is not automatically an attacker. Search crawlers, feed readers and link-preview fetchers are all automated, and all welcome. They are counted as bots because that is what they are, not as a judgement.

Most 404 traffic is noise. A request for /.env or /wp-login.php is a script working through a wordlist. It is worth counting because it shows what is being tried against ordinary servers, but a 404 means the server simply did not have the file.

GeoIP is approximate. Country data comes from an address lookup and is reliable at country level at best; VPNs, cloud regions and mobile carriers regularly place a host somewhere unexpected.

One day is a small sample. Use the date picker to compare days before drawing a conclusion from a spike.

Data and API

The data behind these pages is served from api.oldhat.dev, both as JSON and as pre-rendered HTML fragments (the pages here request a fragment and swap it into place). The report can be followed live: the Go Live button on any section page opens a Server-Sent Events stream and refreshes that section as new data lands.

Full history is browsable by date from each page. A health check is available at api.oldhat.dev/v1/health.

Source

The frontend is open source: github.com/angelomadara/oldhat.dev. It is plain HTML, CSS and Alpine.js with no build step.
